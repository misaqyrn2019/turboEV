# انتشار روی Vercel

برای استفادهٔ آنلاین، [راهنمای استقرار Vercel](DEPLOY_VERCEL_FA.md) را ببینید. سه تنظیم سرور برای اتصال Turso و ایجاد مدیر اولیه لازم است؛ Git push به‌تنهایی فایل SQLite و حساب محلی را منتقل نمی‌کند. اجرای محلی مطابق راهنمای زیر همچنان پشتیبانی می‌شود.

# سامانه مدیریت ناوگان مپنا

برنامهٔ وب فارسی، راست‌به‌چپ و سازگار با دسکتاپ و موبایل، بر اساس گزارش عملیاتی توسن–ماهکس و نماهای صفحات ۲۶ تا ۳۶ ساخته شده است. امکان ثبت و ویرایش اطلاعات واقعی وجود دارد. دادهٔ نمایشی صرفاً برای آزمایش و ارائه است.

## صفحهٔ ورود تعاملی و هویت مپنا

رابط با لوگوی مپنا و پالت سرمه‌ای، آبی و فیروزه‌ای طراحی شده است. در نمایشگرهای بزرگ، اسکرول طبیعی صفحه بین سه صحنهٔ حرکت، انرژی و مدیریت جابه‌جا می‌شود و فرم ورود ثابت می‌ماند. حرکت ماوس عمق صحنه را تغییر می‌دهد؛ کارت‌های انرژی و مدیریت نیز توضیحات قابل باز شدن دارند. در موبایل و پنجره‌های کوتاه، دکمه‌های انتخاب صحنه در دسترس هستند.

کلیدهای بالای صفحه نمای روز/شب و توقف حرکت‌ها را کنترل می‌کنند. تنظیم کاهش حرکت سیستم‌عامل رعایت می‌شود و فرم با صفحه‌کلید و تکمیل خودکار مرورگر کار می‌کند. نمودارها و صفحات مدیریتی پس از نیاز بارگیری می‌شوند تا ورود سبک‌تر باشد.

نام پیش‌فرض سازمان‌های قدیمی به «مپنا» تغییر می‌کند؛ نام سفارشی سازمان، اطلاعات عملیاتی، کاربران و رمزها حفظ می‌شوند. تصاویر اسلایدهای اصلی بدون تغییر نگهداری شده‌اند. منابع لوگو در `public/media/brand/SOURCES.md` ثبت شده‌اند.

## اجرای سریع

فایل **`start.cmd`** را اجرا کنید و سپس این آدرس را در مرورگر باز کنید:

**http://127.0.0.1:8000**

پنجرهٔ اجرا باید باز بماند. با `Ctrl+C` سرویس متوقف می‌شود. اطلاعات در فایل SQLite باقی می‌مانند.

- نام کاربری اولیه: **`admin`**
- رمز تصادفی اولیه: در **`data/initial-credentials.txt`**
- تغییر رمز: **تنظیمات ← رمز عبور**
- مدیریت حساب‌ها: **تنظیمات ← کاربران و نقش‌ها**

در اجرای نخست روی رایانهٔ جدید، Python 3.11 یا بالاتر لازم است. اگر پوشهٔ `dist` موجود باشد، برای اجرای روزمره نیازی به Node.js یا اینترنت نیست. در صورت نبود وابستگی‌های Python، اسکریپت آن‌ها را نصب می‌کند. برای ساخت مجدد رابط، Node.js 22.12+ یا 24 مناسب است.

رمز اولیه فقط بار اول ایجاد می‌شود؛ اجرای مجدد برنامه رمز یا داده‌ها را بازنشانی نمی‌کند. فایل رمز اولیه بعد از تغییر رمز، رمز جدید را نمایش نمی‌دهد.

## منظور از صفحهٔ استاتیک و SQLite

خروجی رابط کاربری، فایل‌های استاتیک HTML، CSS و JavaScript در `dist/` است. ورود واقعی، اعمال سطح دسترسی و خواندن/نوشتن SQLite با یک سرویس محلی FastAPI انجام می‌شود. مرورگر به‌تنهایی و با دوبار کلیک روی `index.html` نمی‌تواند این امکانات را اجرا کند؛ برنامه باید از آدرس بالا باز شود.

پایگاه اصلی: **`fleet_web/data/fleet.sqlite3`**. داده‌ها در `localStorage` یا حافظهٔ موقت مرورگر نگهداری نمی‌شوند. بستن مرورگر یا خاموش کردن سرویس باعث پاک شدن اطلاعات نمی‌شود. سرویس فقط روی `127.0.0.1` گوش می‌دهد.

## شروع کار واقعی

1. **مراکز توزیع:** مرکز، شهر، مسئول، ظرفیت برق و وضعیت تأیید ایمنی را ثبت کنید.
2. **ناوگان:** گروه ناوگان را به مرکز متصل و مسئول عملیات و خدمات فنی را مشخص کنید.
3. **رانندگان:** پرونده و وضعیت آموزش راننده را ثبت کنید.
4. **باتری‌ها و شارژرها:** شناسه‌ها، مرکز، ظرفیت و اطلاعات اولیه را ثبت کنید.
5. **موتورسیکلت‌ها:** موتور خریداری‌شده را با نوع برقی یا بنزینی، مدل، پلاک، VIN، فاکتور، تأمین‌کننده، مبلغ و تاریخ خرید، گارانتی، ناوگان، راننده و باتری ثبت کنید.
6. **کنترل پیش از شیفت:** نتیجه بازرسی ایمنی، باتری، شارژر، داده و پشتیبانی را ثبت کنید؛ نتیجهٔ «تأیید شده» کنترل‌های پایه موتور را به‌روز می‌کند. راننده و شیفت هر کنترل قابل ثبت است.
7. **مأموریت‌ها:** زمان شروع، مسیر، موتور و راننده را تخصیص دهید. با تغییر وضعیت به تکمیل یا ناموفق، نتیجه، مسافت و شارژ پایان را وارد کنید.
8. **مدیریت شارژ:** نوبت شارژ را با موتور و شارژر ایجاد کنید. برای اتمام، وضعیت «تکمیل شده» و زمان پایان، شارژ نهایی و انرژی را وارد کنید.
9. **خرابی‌ها:** شدت، مسئول، زمان وقوع، پاسخ، شروع تعمیر، رفع و بازگشت به سرویس را جداگانه ثبت کنید.
10. **کارکرد روزانه:** زمان برنامه‌ریزی‌شده و آماده‌به‌کار، پیمایش، انرژی، بنزین و هزینه را وارد کنید تا گزارش زمانی آماده‌به‌کاری محاسبه شود.

ثبت کنترل شیفت و دروازه‌های پایلوت از تأیید سازمانی مستقل نیست؛ سامانه داده و شواهد ثبت‌شده را نمایش می‌دهد. بررسی الزامات فیزیکی تجهیزات توسط نرم‌افزار انجام نمی‌شود.

## دادهٔ نمایشی

در پایگاه خالی، دکمهٔ «مشاهده داده نمایشی» در داشبورد در دسترس مدیر است. این کار ۱۲ موتور، ۱۰ باتری، ۳ مرکز، رانندگان و سوابق نمونه می‌سازد. همهٔ این رکوردها برچسب داخلی `demo` دارند و بنر نمایشی در تمام صفحات دیده می‌شود.

برای پاک کردن نمونه‌ها: **تنظیمات ← داده و پشتیبان ← پاک‌سازی داده‌های نمایشی**. اطلاعات واقعی و حساب‌های کاربری باقی می‌مانند. اگر رکورد واقعی به مرکز یا دارایی نمایشی مرتبط باشد، پاک‌سازی مسدود می‌شود تا ابتدا ارتباط را اصلاح کنید.

اعداد تصاویر PDF مستقیماً به‌عنوان داده واقعی وارد نشده‌اند. مدل RS7 در داده نمونه به معنای تأیید خرید یا پذیرش فنی این مدل نیست.

## قواعد عملیاتی

- موتور برای تخصیص باید وضعیت پایه «آماده سرویس» داشته باشد. ایمنی، داده و پشتیبانی باید تأیید شده باشند؛ ناوگان و مرکز فعال و ایمنی مرکز تأیید باشد.
- برای موتور برقی، باتری سالم، شارژ کافی، دادهٔ تازه، دمای مجاز، نبود خطای بحرانی BMS و سازگاری شارژر بررسی می‌شود.
- خرابی باز، شارژ فعال یا مأموریت فعال دیگر مانع تخصیص جدید است.
- راننده باید فعال و آموزش‌دیده و متعلق به همان مرکز باشد. تخصیص هم‌زمان یک راننده به دو مأموریت مسدود است.
- اگر شیفت برای مأموریت انتخاب شود، باید فعال، متعلق به همان مرکز و شامل راننده باشد.
- باتری به‌طور هم‌زمان به دو موتور متصل نمی‌شود. پلاک و VIN تکراری پذیرفته نمی‌شوند.
- یک شارژر یا موتور، دو جلسه شارژ فعال هم‌زمان ندارد. موتور بنزینی، باتری معیوب، دمای غیرمجاز و خرابی باز برای شروع شارژ مجاز نیستند.
- ثبت خرابی در حین شارژ، نوبت جاری را در **سوابق نرم‌افزار** ناموفق می‌کند و زمان پایان و ارجاع رخداد را ثبت می‌کند. این عمل فرمان قطع برق به شارژر فیزیکی ارسال نمی‌کند.
- تکمیل مأموریت، مسافت را یک‌بار به کیلومترشمار اضافه می‌کند؛ تکمیل شارژ SOC را به‌روز می‌کند. ورود سابقه قدیمی، اندازه‌گیری تازه‌تر باتری را بازنویسی نمی‌کند.
- مأموریت و شارژ پایان‌یافته قابل بازگشایی یا تغییر مقادیر کارکرد نیستند. اطلاعات توضیحی و پیگیری قابل ویرایش‌اند.
- تاریخ‌ها و بازه اعداد اعتبارسنجی می‌شوند. مقادیر درصد خارج از ۰ تا ۱۰۰، زمان‌های نامرتب و رویدادهای انجام‌شده در آینده رد می‌شوند. برنامه‌ریزی مأموریت آینده مجاز است.
- حذف دارایی دارای ارتباط مسدود است. تغییرات مهم و ورود/خروج در تاریخچه فعالیت ثبت می‌شوند.

## محاسبه شاخص‌ها

- **آماده‌به‌کاری زمانی:** مجموع دقیقه‌های آماده‌به‌کار تقسیم بر مجموع زمان برنامه‌ریزی‌شده در کارکرد روزانه؛ این شاخص با نسبت تعداد موتورهای آماده فرق دارد.
- **توقف زمانی:** مکمل آماده‌به‌کاری زمانی، بر اساس همان کارکردها.
- **زمان بازگشت از خرابی:** اختلاف `restored_at` و `reported_at` برای خرابی‌های بازگشته به سرویس.
- **زمان اولین پاسخ:** اختلاف پاسخ و ثبت درخواست پشتیبانی.
- **موفقیت مأموریت:** مأموریت‌های تکمیل‌شده تقسیم بر مجموع مأموریت‌های تکمیل‌شده و ناموفق؛ مأموریت باز و لغوشده وارد مخرج نمی‌شود.
- **تحقق هدف پاسخ SLA:** پاسخ‌های در مهلت تقسیم بر مجموع درخواست‌های پاسخ‌داده‌شده و درخواست‌های بی‌پاسخ گذشته از مهلت. موارد بی‌پاسخ ولی هنوز در مهلت، ارزیابی‌نشده‌اند.
- **انرژی:** انرژی ثبت‌شده در جلسات شارژ؛ پیمایش و هزینه نگهداری گزارش از کارکردهای روزانه استخراج می‌شود.
- بازهٔ نمودارها بر اساس تاریخ محلی تهران و رکوردهای همین پایگاه است. دادهٔ مفقود با «—» نمایش داده می‌شود.

## CSV

- خروجی فارسی هر صفحه فقط شامل ردیف‌های فیلترشده و مناسب ارائه و Excel است.
- برای ورود، از «قالب ورود» با نام ستون‌های انگلیسی استفاده کنید.
- «تنظیمات ← داده و پشتیبان» خروجی ماشینی قابل ورود مجدد را ارائه می‌کند.
- شناسه‌های مرتبط با `code` مانند `M-001`، `BAT-001` و `FLE-001` نوشته می‌شوند.
- داده بولی: `true` یا `false`. آرایه روزها/رانندگان: آرایه JSON در سلول CSV.
- وضعیت‌ها کلید انگلیسی‌اند. راهنمای کامل فیلدها و مقادیر در [CSV_FIELDS.md](CSV_FIELDS.md) موجود است.
- شناسه تکراری پذیرفته نمی‌شود؛ ورود برای ایجاد رکورد جدید است و رکورد قبلی را بازنویسی نمی‌کند.
- حداکثر ۱۰۰۰ ردیف و ۲ مگابایت در هر فایل. تمام فایل در یک تراکنش وارد می‌شود؛ خطای هر ردیف، همه تغییرات همان فایل را لغو می‌کند.
- ستون‌های خروجی در برابر اجرای فرمول ناخواسته در برنامه‌های صفحه‌گسترده محافظت می‌شوند.

## تاریخ و زمان

نمایش تاریخ‌ها شمسی و با منطقه زمانی تهران است. کنترل استاندارد مرورگر برای ورود تاریخ، مقدار میلادی می‌گیرد؛ راهنما کنار فیلد درج شده است. زمان بدون offset، زمان تهران تلقی می‌شود. شیفت با ساعت پایان کمتر از شروع، شیفت شب محسوب می‌شود. سامانه، اجرای واقعی یک شیفت یا حضور افراد را به‌طور خودکار دریافت نمی‌کند.

## نسخه پشتیبان و بازیابی

از **تنظیمات ← داده و پشتیبان ← دریافت نسخه پشتیبان** فایل `.sqlite3` دریافت کنید. پشتیبان با API داخلی SQLite ساخته می‌شود و با فعال بودن WAL هم سازگار است.

برای بازیابی، ابتدا سرویس را با `Ctrl+C` کاملاً ببندید و یک کپی از پایگاه فعلی نگه دارید. سپس فایل پشتیبان را جایگزین `data/fleet.sqlite3` کنید و سرویس را دوباره اجرا کنید. جایگزینی فایل در زمان باز بودن برنامه انجام نشود. حساب‌های کاربری هم متعلق به همان نسخه پشتیبان خواهند بود.

## محدوده اتصال به تجهیزات

نسخه حاضر با ثبت دستی و CSV کار می‌کند. هیچ اتصال زنده‌ای به GPS، BMS، سخت‌افزار شارژر یا سامانه ماهکس برقرار نشده است؛ قرارداد API، آدرس سرویس و اطلاعات دسترسی این منابع ارائه نشده‌اند. نقشهٔ مراکز نمایش شماتیک مختصات ثبت‌شده است و ردیابی زنده نیست. کلید API نمایشی یا اتصال صوری در برنامه وجود ندارد.

نمودارهای روند فقط از رویدادهای تاریخی موجود ساخته می‌شوند. برای SOC/SOH نمودار توزیع و میانگین وضعیت فعلی ارائه شده؛ تاریخچه نمونه‌برداری تله‌متری خودکار در این نسخه تولید نمی‌شود. اهداف و هشدارها تضمین فیزیکی آماده‌به‌کاری یا مجوز شروع پایلوت نیستند.

## فناوری و توسعه

- React **19.3.0**، TypeScript **7.0.2**، Vite **8.3.1**
- FastAPI **0.141.1**، Uvicorn **0.54.0**
- SQLite با WAL، تراکنش نوشتن و اعتبارسنجی ارتباط‌ها
- Argon2id برای هش رمز عبور، کوکی HttpOnly و SameSite، توکن CSRF، محدودیت تلاش ورود و تاریخچه فعالیت
- Recharts **3.10.1**، Lucide، فونت محلی Vazirmatn؛ همه دارایی‌های رابط به‌صورت محلی ساخته می‌شوند

نسخه‌ها در `package.json` و `package-lock.json` ثابت شده‌اند. مرجع نسخه‌های رابط: [React](https://react.dev/versions) و [Vite](https://vite.dev/guide/). معماری استاتیک رابط مطابق [راهنمای ساخت Vite](https://vite.dev/guide/build) است.

اجرای توسعه در دو ترمینال، از پوشه `fleet_web`:

```powershell
..\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload
```

```powershell
npm ci
npm run dev
```

ساخت نسخه نهایی:

```powershell
npm run build
```

آزمون API از `G:\Project`:

```powershell
.\.venv\Scripts\python.exe -m pytest fleet_web/backend/test_app.py -q
```

آزمون مرورگر از `fleet_web` (Chrome نصب‌شده لازم است):

```powershell
npm test
```

تست مرورگر پایگاه جدا در `qa/` و سرویس جدا روی پورت ۸۰۰۱ ایجاد می‌کند و دادهٔ اصلی را تغییر نمی‌دهد. تصاویر دسکتاپ، موبایل و فرم خرید در `qa/` قرار می‌گیرند. حساب تست `Fleet-QA-Password-2026` فقط در پایگاه آزمایش ساخته می‌شود و رمز مدیر اصلی نیست.

متغیرهای اختیاری:

- `FLEET_DB`: مسیر پایگاه SQLite مستقل
- `FLEET_ADMIN_PASSWORD`: رمز مدیر فقط هنگام ایجاد پایگاه جدید
- `FLEET_HTTPS=1`: کوکی Secure برای استقرار HTTPS؛ در HTTP محلی فعال نشود

این پروژه در پوشهٔ مستقل `fleet_web` ساخته شده و برنامه زمان‌بندی CPU و فایل‌های قبلی پروژه را تغییر نمی‌دهد.
